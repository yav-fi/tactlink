# Webcam gesture control for a simulated quadcopter

Completed: 2026-09-05 12:20:36 PM EDT (America/New_York)

## Prompt

"I need help building a webcam visualization software that will help control
movements of a quadcopter." Clarified with the user: track **hand gestures**
(MediaPipe), control a **simulator / visualization only** (no real drone), in
**Python (OpenCV + MediaPipe)**.

## What changed

New application under `src/`:

- `control_types.py` - `HandState` and `ControlInput` dataclasses shared across
  the pipeline.
- `hand_tracker.py` - wraps the MediaPipe Tasks `HandLandmarker` (VIDEO mode).
  Derives palm position, hand roll angle, a camera-distance-invariant pinch
  ratio, and an extended-finger count. Auto-downloads `hand_landmarker.task`
  into `models/` on first use. Draws the landmark skeleton onto the frame.
- `controls.py` - `GestureController` maps a `HandState` to a normalized
  `ControlInput` with centered dead zones and first-order smoothing. Open palm
  arms, fist disarms; palm x/y drive yaw/throttle; hand tilt drives roll; a
  pinch drives forward pitch (gated on an open-enough hand).
- `simulator.py` - `QuadSimulator`, an arcade quadcopter model in a world frame
  (x right, y forward, z up). First-order velocity response, yaw integration,
  gravity sink when disarmed, ground clamp, visual bank/pitch lag, rotor spin
  phase, and a position trail.
- `visualizer.py` - a look-at pinhole `Camera` plus a renderer that draws a
  ground grid, the trail, a shadow, the drone (X-arms, spinning rotors, nose
  marker), and a HUD (arm state, altitude/speed/yaw, control bars, gesture
  events). A chase camera eases toward the drone so it stays framed.
- `main.py` - capture loop compositing the webcam feed beside the 3D view.
  Flags: `--camera N`, `--demo` (scripted hand path, no camera/model),
  `--headless` + `--out` (render a sample frame and exit), `--duration`.
  Keys: `q` quit, `r` reset, `space` force-arm toggle.

Also: `requirements.txt`, `.gitignore` (ignores `models/`, `__pycache__/`,
`*.png`, venvs), and README rewritten with setup, run modes, and the gesture
table.

## Verification

- `python -m py_compile src/*.py` - clean.
- Logic test of `GestureController` + `QuadSimulator`: open-palm input arms and
  flies the drone; switching to a fist disarms and it settles to `z=0` /
  `on_ground=True`. Caught and fixed a bug where `QuadState.armed` was never
  assigned from the command.
- `python src/main.py --demo --headless --duration 10 --out flight_demo.png` -
  renders a 1600x720 composite; inspected frames at t=5s (armed, climbing,
  banking, chase cam tracking, trail/grid following) and t=10s (fist -> disarmed,
  landed, rotors idle). Fixed a bug where the trail lived on the simulator but
  the visualizer read it from the state.
- `HandTracker` smoke test on a random frame: initializes, downloads the model,
  returns `present=False`, `draw()` no-ops safely.
- `HandTracker` on real MediaPipe sample images: `fist` -> 0 fingers,
  `pointing_up` -> 1, `thumb_up` -> 1, `right_hands`/`left_hands` -> 5. The
  arm/disarm gates (>=4 and ==0) are reliable; mid counts (e.g. `victory` -> 3)
  are approximate but unused. Fixed a crash where non-increasing
  `detect_for_video` timestamps raised `ValueError` (now a strictly increasing
  stamp).

Live webcam capture was not tested in this environment (no camera); the tracker
was validated against still images instead.

## Notes, assumptions, limitations

- The installed stack resolved to `opencv-python`/`opencv-contrib-python`
  5.0.0.93, `mediapipe` 1.0.1, `numpy` 2.4.6 on Python 3.11 / Windows.
  MediaPipe 1.x removed the legacy `mp.solutions` API, so the tracker uses the
  Tasks API and an external `.task` model bundle.
- A concurrent `pip install` locked `cv2.pyd` and left the first install
  partial; a `--force-reinstall --no-deps` of the opencv packages repaired it.
- The simulator is arcade physics tuned for a stable, readable demo, not flight
  dynamics.
- `models/` is gitignored; the model is fetched on first live run.
