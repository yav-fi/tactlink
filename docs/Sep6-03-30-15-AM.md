## Fast test procedure

From the repository root, start the existing bootstrap with the phone receiver exposed to the trusted local Wi-Fi:

```sh
PHONE_FEED_HOST=0.0.0.0 SIMULATION_DRONE_COUNT=5 ./start --no-open
```

Open http://127.0.0.1:5173/?mode=runtime on the Mac. The HTTP server can remain loopback because phones send UDP directly to the LAN-bound receiver. Ensure no old backend is reused with the wrong environment; the launcher reuses any existing server on port 8000.

On five physical UWB-capable iPhones: install the same current SignalMap build, keep Wi-Fi and Bluetooth enabled, grant Local Network/Nearby Interaction/camera permissions, disable the three-phone flat test toggle, create one room and join it from the other four. Set every Visualizer host to the Mac's Wi-Fi IP followed by :9870. Keep the app foreground and wait for the shared map. Check /api/operators for five entries and the runtime map for five people. Hold thumb-up or open-palm gestures for at least 0.4 seconds; observe control lines and gesture-sourced missions at /api/missions. Frame placement/rotation can be adjusted through /api/operators/frame.

Without physical phones, run this in another terminal:

```sh
.venv/bin/python scripts/mock_phone_feed.py --phones 5 --still --script
```

Stop the mock feed before using real phones so synthetic operators do not affect control selection. The optional local mission AI is not required for phone gesture integration.
