# Gesture combos (ordered sequences)

Completed: 2026-09-05 01:25:15 PM EDT (America/New_York)

## Prompt

"Would it be possible to add multi hand gestures together in a sequence to mean
something... open palm, palm closed, palm open in a ~3 second window as a
command." Decisions from the follow-up: **one-hand sequential combos** (not
simultaneous two-hand), and conflicts with single-gesture commands handled by
**delay-and-cancel** (a single-gesture action is held back briefly and cancelled
if it turns out to be part of a completed combo).

## What changed

- `src/sequences.py` (new) - `SequenceMatcher`: keeps a rolling buffer of stable
  gesture "tokens" and fires when the buffer tail equals a configured pattern
  within its time window. `prefix_active()` reports an in-progress partial match
  (used to hold single-gesture commands) with a 1.0 s idle cutoff. `load_config()`
  reads `config/gesture_sequences.json`.
- `config/gesture_sequences.json` (new) - one example combo
  (`Open_Palm > Closed_Fist > Open_Palm` -> `return_home`) plus `single_delay`
  (0.6 s). Absent file / empty `sequences` -> no combos and zero added delay.
- `src/gestures.py` - `GestureInterpreter` now:
  - emits a combo token when a gesture is held `SEGMENT_SEC` (0.18 s) and differs
    from the last token; a >=0.18 s gap at "None" resets so a repeated pose is a
    fresh token;
  - defers a single-gesture command into `_pending` when that gesture appears in
    any pattern and `single_delay > 0`; other gestures fire immediately as before;
  - releases a pending command after `single_delay` unless a partial combo is
    live; clears all pendings when a combo fires.
  - Constructor takes optional `matcher` / `single_delay` for testing.
- `src/control_types.py` - `GestureState.sequence_hint`.
- `src/visualizer.py` - HUD shows `combo: A>B>…` while a partial combo is live.
- `src/main.py` - demo timeline now performs an open/fist/open combo (~t=16.5-21)
  that fires return-home, with the individual poses correctly *not* triggering
  takeoff / land.

## Verification

- `python -m py_compile src/*.py` - clean.
- Interpreter unit tests (scripted clock):
  - lone `Open_Palm` -> `takeoff` (fires ~1.2 s later: held through the
    single-delay + prefix-idle grace since it is a combo prefix);
  - `Open_Palm -> Closed_Fist -> Open_Palm` with gaps -> only `return_home`
    fires, no stray `takeoff` / `land`;
  - `Closed_Fist -> Closed_Fist` against an estop combo -> `estop` (double-token
    via the None-gap reset).
  - No config file -> lone `Open_Palm` fires `takeoff` immediately, no hint
    (unchanged behavior).
- `python src/main.py --demo --headless` at t=13/19/23/29 s: partial-combo HUD
  shows during the poses, drone keeps flying (poses suppressed), then flies home
  after the third pose, then lands on the final fist. 1040 frames, ends disarmed.

## Notes / limitations

- Two-handed *simultaneous* gestures were explicitly deferred; the tracker is
  still `num_hands=1`.
- Gestures used in a pattern get the `single_delay` (~0.6 s) latency; the shipped
  config only puts `Open_Palm` / `Closed_Fist` in a pattern, so Victory / thumbs /
  point / ILoveYou stay snappy.
- A *fumbled* combo (partial then a different gesture) can still let the earlier
  poses' single commands fire once the partial match goes idle. Acceptable for a
  demo; tune `single_delay` / `PREFIX_IDLE_SEC` if it bites.
- `src/flight_language.py` and the `planning/` `simulation/` trees are teammates'
  workstreams - untouched.
