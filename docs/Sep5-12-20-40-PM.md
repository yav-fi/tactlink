# Default benchmark to 1 rep

Completed: 2026-09-05 12:20:40 PM EDT

## Prompt

Change the benchmark's default rep count from 3 to 1 (3 was too much).

## What changed

- `scripts/benchmark.py`: `--reps` default changed from `3` to `1`; updated the usage
  docstring to match.
- `README.md`: updated the benchmark section's description to reflect the new 1-rep
  default (median is only reported/meaningful when `--reps` is explicitly raised above 1).

## Verification

- Ran `./scripts/benchmark.py` with no `--reps` flag against the live server: completed
  one thermally-gated rep and reported a real, receipt-verified result — 512 tok in
  7.08s -> **72.3 tok/s decode**, cooldown to 37.4°C, fans verified at manual/max RPM
  pre- and post-run, released to auto afterward. Matches `benchmark_result.json`.
- Along the way, two earlier attempts with the old 3-rep default hit a real
  `ThermalComplianceError` (fans didn't reach 90% max RPM within the 20s grace window) —
  confirmed this was a transient `thermalforge` daemon flake, not a systemic bug: a
  manual `thermalforge max` retry immediately afterward worked fine (ramped to
  >90% within ~2s). The gate did exactly what it's supposed to do: hard-fail rather than
  publish an unverified number.

## Notes, assumptions, limitations

- The transient `thermalforge max` flake isn't retried anywhere in the current chain
  (`mlx-bench`'s `assert_fans_max` calls it once, no retry-with-backoff) — if this keeps
  recurring, worth adding a retry loop either in `mlx-bench` itself (upstream, shared
  fix) or as a local wrapper in `benchmark.py`. Not fixed here since it resolved with a
  simple re-run; flagged for later if it becomes a recurring annoyance.
