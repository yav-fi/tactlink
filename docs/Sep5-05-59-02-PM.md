## Notes, assumptions, limitations, and follow-up

- This is a deterministic software simulation and is not validated for live or
  safety-critical flight.
- The communication-belief overlay intentionally shows only distributed node
  beliefs, not simulator ground truth. The host necessarily retains physics
  truth while external workers receive node-local inputs only.
- Baseline node-loss recovery is nearly immediate because centralized control
  observes host truth; fabric recovery takes the configured peer timeout and
  re-auction path. The benchmark reports both rather than hiding the tradeoff.
- Qwen latency is hardware- and thermal-state-dependent. The recorded local
  512-token thermal benchmark is 47.576 decode tok/s on the Apple M4 16 GB host;
  the mission evaluation mean is 47.19 tok/s.
- The installed Qwen 9B DFlash draft is v1 and exposes no DFlash2 selector
  confidence, so LibraSpec is automatically disabled instead of paying its
  synchronization cost for no pruning benefit.
- macOS screen capture was unavailable and Safari remote automation was disabled.
  Visual verification therefore used the live rendered Safari DOM plus backend
  WebSocket/API acceptance rather than an automated screenshot.
- A single over-complex natural-language sentence asking for search, relay,
  percentage-triggered return, and “all units” can be conservatively rejected
  when the model emits percent values outside the 0..1 schema or counts
  sequential RETURN resources cumulatively. The reliable demo uses a confirmed
  search+relay plan followed by a typed recall amendment, which also shows the
  intended human-in-the-loop workflow.
