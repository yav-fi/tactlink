# Operators stand still; orbit & return-home anchor on the operator

Completed: 2026-09-05 07:50:37 PM EDT (America/New_York)

## Prompt

1. The operator paces around randomly - stop that.
2. `orbit` should circle the (controlling) operator, not the origin.
3. `return_home` should return to the operator, not the origin.

## What changed

- `src/operators.py`:
  - `wander_enabled` now defaults **False** - operators stand still until real
    phone positions drive them.
  - `set_active_by_proximity` gained **hysteresis** (0.72): control only flips
    when the new nearest operator is clearly closer, so it doesn't flicker while
    the drone passes between two people.
- `src/controls.py`:
  - `GestureController` tracks `self._anchor` = `GestureState.follow_pos` (the
    controlling operator's xy), updated each `update()`, defaulting to the origin.
  - `orbit` circles `_anchor` (radius `_ORBIT_RADIUS` cut 10 -> 6 m, nose still
    inward); `return_home` flies to `_anchor`.
- `src/main.py`:
  - `--wander` flag (opt-in walking, ignored in `--demo`).
  - demo operators spaced 12 m apart (was 6) so an orbit around one doesn't reach
    a neighbour.
- Tests: `test_operators` +1 (hysteresis), `test_fly_maneuver` +2 (orbit circles
  the anchor / return-home goes to the anchor).

## Verification

- `python -m py_compile src/*.py tests/*.py` clean; all suites green
  (operators 6, finger_swing 9, fly_maneuver 12, swarm 5, sequences 10).
- `--demo` render mid-orbit: `CTRL op2` stable, the 5-drone swarm circling op2's
  position (trail is a ring centred on op2), not the origin.

## Notes

- With no operators effectively in play (`--operators 1`, default), `_anchor` is
  that one operator's fixed ring position, so orbit/return-home target it. To get
  the old "everything around the origin" behaviour, put an operator at (0,0).
- `_ORBIT_RADIUS` and the hysteresis factor are constants; tune if a swarm orbit
  still clips a neighbouring operator.
