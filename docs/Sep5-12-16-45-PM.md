# Thermal-gated tok/s benchmark

Completed: 2026-09-05 12:16:45 PM EDT

## Prompt

Add a benchmark script that properly measures tok/s "for any computer," importing the
best reusable patterns from `mlx-bench`, `dartree-mlx`, and `dflash2-mlx` rather than
reinventing them. Interviewed first (research fork surveyed all three projects), then
confirmed scope: single-config only (this project's DFlash2+LibraSpec setup, accepted as
the best-performing one — no serial/no-LibraSpec sweep), 3 reps median gated per rep
(matching the house standard across those projects), reuse `mlx-bench`'s thermal-gate
implementation by import rather than vendoring a copy (same pattern dartree-mlx uses),
simple stdout + one JSON file output.

## What changed

- Added `scripts/matched_prompt.txt`: a fixed prompt so every run/machine gets
  byte-identical input (an unmatched prompt previously caused a wrong benchmark number
  in dflash2-mlx's own history — this avoids repeating that).
- Added `scripts/benchmark.py`: imports `~/mlx-bench/core/thermal.py` (public MIT repo,
  same convention `dartree-mlx/scripts/thermal_gate.py` uses) rather than reimplementing
  GPU thermal gating a third time; fails with a clear one-line clone instruction if it's
  not present, and respects `MLX_BENCH_DIR` for a non-default clone location. Runs 1
  discarded warmup + 3 reps of the fixed prompt (512 max tokens) against the chat
  server's `/completion` endpoint via `chat_client.chat_sync`, each rep wrapped in
  `thermal.gated_run()` (cooldown-wait to 40°C, fan-RPM-verified, printed compliance
  receipt, released to auto after). Reads decode tok/s directly from the server's own
  `predicted_n`/`predicted_ms` timings (no wall-clock-subtraction trick needed, unlike
  dflash2-mlx's `http_api_bench.py`, since chad serve already reports per-request
  prefill/decode split). Prints per-rep + median tok/s, writes full detail (timings +
  thermal receipts) to `benchmark_result.json`.
- Added `scripts/benchmark.sh`: ensures the server is up (same auto-start pattern as
  `ask.sh`) before running `benchmark.py`.
- `.gitignore`: added `benchmark_result.json` (local generated artifact).
- Documented the one-time `git clone https://github.com/kaarelkaarelson/mlx-bench.git
  ~/mlx-bench` setup step and usage in `README.md`.

## Verification

- Ran `./scripts/benchmark.sh --reps 3 --max-tokens 512` for real (GPU already cool at
  34°C going in) against the running server (mlx-community 4bit + w4:gs64 DFlash2 +
  LibraSpec via the private fork). Got three real, individually gated reps — 72.1, 71.7,
  72.3 tok/s decode, median **72.1 tok/s** — each with a printed compliance receipt
  showing pre/post-run fan RPM at ≥90% of max and cooldown temps ~36-37°C. Confirmed
  `benchmark_result.json` was written with matching detail.
- This is a real measurement on this machine, not a citation from dflash2-mlx's README
  (~65-66 tok/s there) — the two numbers aren't meant to match; different
  machine/session, only the methodology is shared.

## Notes, assumptions, limitations

- Requires a one-time `git clone` of the public `mlx-bench` repo — not vendored, so
  DNHacks stays in sync with that project's thermal-gate hardening automatically, but
  the clone step is a real prerequisite this README now documents.
- No early-EOS-disable trick (unlike `chad_matched_bench.py`'s in-process
  `eng._eos_ids = lambda: set()`) — the HTTP `/completion` API has no such override, so a
  rep could in principle stop before `--max-tokens` if the model hits EOS early; tok/s is
  still computed correctly from actual generated tokens either way, just noting the
  generation length isn't hard-pinned across reps the way the in-process tools force it.
- Single-configuration only, by design (this session's explicit decision) — if a
  serial/no-LibraSpec comparison is wanted later, the script would need `--legs` support
  and server-restart logic, neither of which exists yet.
