# Phones on the lawn: live operators in the mission runtime

**Completed:** 2026-09-06 02:42:14 EDT (-0400)

## Prompt

Several iPhones cooperatively estimate their own positions. One phone stands for
a chosen point on the lawn in front of the Washington Monument and the others sit
relative to it. All of them publish through to the runtime, so the web console at
`127.0.0.1` shows three or more people standing on the ground beside the drones.
Their hand commands are interpreted, and the person **closest to a drone** is the
one that drone acts on. The prompt also asked to find a way for the iOS app to
publish stats the server can read, if that did not already exist.

## What already existed (and was preserved)

The publishing side was **already built** and needed no iOS change:

- `ios/SignalMap/RoomBridge.swift` streams each phone's own group-frame position,
  absolute magnetic compass facing, and locally recognized gesture as small JSON
  datagrams over UDP, ~10 Hz, to a "Visualizer host" set in the app lobby.
- `ios/SignalMap/GestureCamera.swift` already does on-device Vision hand-landmark
  recognition and emits labels matching `config/gesture_actions.json`, including
  `Dash_Left`, `Dash_Right`, and `Three_Finger_Forward`.
- `src/operators.py` / `src/operator_gestures.py` already implement per-operator
  gesture timing and nearest-operator control — but only for the standalone
  OpenCV app (`src/main.py`), which is not the `127.0.0.1` web console.

The real gap was on the **receiving** side: `server/main.py` never listened for
phones, `SimulationSnapshot` carried no people, and the Cesium runtime had no
concept of a human on the ground. `simulation.models.OperatorPositionUpdate`
existed as an unused contract. That gap is what this change closes.

## What changed

### Backend

- **`simulation/operators.py`** (new). Turns phone reports into placed people.
  - `OperatorFrame` pins the arbitrary UWB group frame onto the scene: a
    nominated **anchor phone** stands at a chosen point and everyone else keeps
    their measured offset from it, rotated by `rotation_deg`. Pairwise ranging
    observes the group's *shape* but never its absolute translation or rotation,
    so this pinning is a declared convention, not a measurement.
  - Nearest-operator control is decided **per drone**, with 0.72 hysteresis so
    control does not flicker as a drone passes between two people.
  - Gestures are *held, not tapped*: a label must stay steady for 0.4 s, fires
    once, and cannot fire again until the hand changes. Latching is per operator,
    so one person's timing never bleeds into another's.
  - `gesture_mission()` translates a fired gesture into a `MissionCommand`.
- **`simulation/models.py`** — added `OperatorFrame` and `OperatorState`, and a
  new `operators` list on `SimulationSnapshot`.
- **`simulation/simulation.py`** — the engine owns an `OperatorRegistry`,
  refreshes it each tick, and submits gesture-driven missions.
- **`server/phone_listener.py`** (new) — asyncio UDP intake bound in the FastAPI
  lifespan, parsing the *existing* `RoomBridge` datagram. A phone already in the
  field needs no rebuild: it just points at the runtime host.
- **`server/main.py`** — `GET/POST /api/operators` and `GET/POST
  /api/operators/frame`, plus lifespan management of the UDP listener.

### Frontend

- **`3d-mapping/src/runtime/layers/operators.ts`** (new) — one marker per person
  standing on terrain, a facing arrow, and a dashed leader line to every drone
  currently listening to them. The leader line is the point of the layer: silent
  control handoff is otherwise invisible.
- **`3d-mapping/src/runtime/icons.ts`** — `operatorIcon()`, a head-and-shoulders
  figure so people do not read as another aircraft class, with a control ring.
- **`types.ts` / `index.ts`** — `RuntimeOperator` type and layer wiring. A
  snapshot without `operators` is treated as "nobody in the field" rather than
  invalid, so an older backend still renders.

## Gesture vocabulary in runtime mode

The runtime's task vocabulary differs from the standalone simulator's autopilot
routines, so two gestures are mapped to the nearest runtime equivalent:

| Gesture | Action | Runtime command |
| --- | --- | --- |
| Thumb_Up | takeoff | `GOTO` above the controlling operator, 25 m |
| Thumb_Down | land | `GOTO` the drone's own x/y at 2 m |
| Open_Palm | halt | `HOLD` (no destination) |
| Pointing_Up | watch_me | `WATCH` aimed at the operator — the runtime has no orbit primitive |
| ILoveYou | return_home | `GOTO` where that person is standing, 15 m |
| Three_Finger_Forward | fly_forward | `GOTO` 25 m along the operator's own facing |
| Dash_Left / Dash_Right | fly_left / fly_right | same, ±90° |
| Closed_Fist, Victory | — | inert, as in `config/gesture_actions.json` |

Dashes resolve against the **operator's compass facing**, so "forward" means
forward for the person who signalled it.

## Notes, assumptions, limitations

- **Not verified with three real iPhones.** Everything above used the mock UDP
  publisher, which emits the same datagram shape as `RoomBridge`. Field
  verification and the magnetic-declination/mount-angle constant
  (`OperatorFrame.rotation_deg`) still need real phones.
- **The anchor point is a convention.** UWB cannot supply absolute position or
  north. The default places the anchor 45 m south of the scene origin
  (38.8895, -77.0353 — already the Washington Monument), just in front of the
  drone staging line. Change it via `POST /api/operators/frame`.
- **Gesture missions are auctioned, not pinned.** The task is submitted to the
  ordinary allocator rather than forced onto the commanded drone. In practice the
  addressed drone wins it because the target sits next to that drone and bids are
  distance-based, but a better-placed peer may take it. `metadata.addressed_to`
  records the intent either way. Pinning would mean bypassing the fabric's
  auction, which the architecture deliberately routes everything through.
- **One person near several drones commands all of them.** With a single operator
  and three drones, that person is nearest to all three, so one gesture issues one
  mission per drone. This is the consistent reading of "the closest person
  commands it" and is asserted in the tests.
- **The UDP feed is unauthenticated** and therefore binds `127.0.0.1` by default.
  Set `PHONE_FEED_HOST=0.0.0.0` to accept phones from the LAN, and only on a
  trusted network. `PHONE_FEED_PORT=0` disables it; HTTP ingest still works.
- **Determinism is preserved.** With no phone publishing, the registry is empty
  and the tick hook is a no-op, so seeded runs and the benchmark are unaffected.
  Phone arrival times and gesture holds use a wall clock, injectable for tests.
- Simulation only; no real-aircraft control was added.
