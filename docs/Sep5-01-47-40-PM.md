# Safe testing for gesture combos

Completed: 2026-09-05 01:47:40 PM EDT (America/New_York)

## Prompt

"What's the safest way to test the sequential hand gestures."

## Answer, layered safest -> most realistic

1. `python tests/test_sequences.py` - deterministic, no camera / sim / drone /
   deps. Fake clock, exact timing.
2. `python src/main.py --demo --check-gestures --headless` - whole recognition
   pipeline on the scripted timeline, prints what would fire.
3. `python src/main.py --check-gestures` - live webcam, real hand tracking, HUD
   and event log only; the (simulated) drone does not move, nothing is submitted.
4. `python src/main.py` - live webcam + simulator (still nothing physical).
5. `--mission-url ...` - actually submits missions; only after 1-4.

Plus: while tuning a combo, map it to a harmless action (`speed_up`).

## What changed

- `tests/test_sequences.py` (new) - 8 standalone tests (run with plain `python`
  or `pytest`): no-config immediate fire, lone combo-member delayed fire, full
  combo fires + suppresses singles, realistic-gap combo, out-of-window combo
  falls back to singles, non-combo gesture not delayed, double-token needs a gap,
  partial-combo hint.
- `src/main.py` - `--check-gestures` dry-run mode: skips the controller /
  simulator / mission submit, renders `_gesture_check_panel` (gesture + source +
  hold bar + combo hint + scrolling fired-event log) and prints each event.
  Spacebar guarded for the no-sim case.
- `src/gestures.py` - **bug fix found via `--check-gestures`**: combo poses with
  realistic ~0.4 s gaps were still firing their single-gesture commands, because
  `prefix_active` measures idle time from the last *token* (emitted at pose
  start) so a 0.7 s pose + 0.4 s gap looked idle. Added `_combo_touch` (updated
  every frame a combo-member gesture is held) and a `COMBO_GRACE_SEC` (0.9 s)
  window during which pending singles stay held.
- `src/main.py` demo timeline - tightened the combo poses to fall inside the 3 s
  window (they were spanning 3.8 s, so the combo silently never fired - the
  drone only *looked* like it went home because of the scripted flight path).
- README - `--check-gestures` in the run list and a "Testing gestures safely"
  note.

## Verification

- `python tests/test_sequences.py` -> 8/8.
- `python src/main.py --demo --check-gestures --headless --duration 24` event
  log: `takeoff` 3.9 s, `mode: position` 7.4 s, `spin360` 12.4 s, `return_home`
  18.9 s - the combo fires and its open/fist poses do **not** fire takeoff/land
  (before the fix the log showed stray `takeoff` 17.7 / `land` 18.8).
- `python src/main.py --demo --headless` still renders the full flight.
- `py_compile` clean.

No camera available here, so the live `--check-gestures` window was not
exercised; the headless equivalent and unit tests cover the same code.

## Notes / limitations

- A lone `Open_Palm` / `Closed_Fist` (combo members) now takes ~1.5 s to fire its
  single command (HOLD 0.4 + single_delay 0.6 + grace 0.9). Non-combo gestures
  are unaffected. Tune `COMBO_GRACE_SEC` / `single_delay` if it feels slow.
- `--check-gestures` ignores `--mission-url` (safety - it never submits).
