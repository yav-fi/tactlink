# DFlash2 chat backend

Completed: 2026-09-05 11:43:21 AM EDT

## Prompt

Plan and bring over the benchmarked DFlash2 speculative-decoding "chat" server from the
user's `dartree`/`dflash2-mlx` work into this project, in the most modular way, using the
best-performing spec-decoding setup. Corrected mid-work: use the
`mlx-community/Qwen3.8-27B-4bit` target with a DFlash2 4-bit draft (not chad's own
default bundled `nathansutton` model — that number, ~100 tok/s, is for a different
model/quant pair). Also include the user's in-progress LibraSpec algorithm on top.

## What changed

- Added `scripts/start_chat_server.sh`: launches `chad serve` (the MLX chat server from
  [`chad-code`](https://pypi.org/project/chad-code/)) as a local sidecar process. No chad
  source lives in this repo.
  - Pins the target to `models/qwen3.8-27b-4bit` (already set up) and the draft to
    `models/dflash2-w4gs64` via `CHAD_MODEL`/`CHAD_DFLASH_PATH`, instead of chad's own
    default bundled model.
  - Prefers a local checkout of the user's private LibraSpec-enabled chad fork
    (`CHAD_REPO_DIR`, default `~/dflash2-mlx/runtime/chad`) via `uv run --project`, and
    falls back to the public `chad-code` PyPI package (no LibraSpec) when that checkout
    isn't present.
- Added `scripts/build_dflash_draft.sh`: builds `models/dflash2-w4gs64` from the public
  `z-lab/Qwen3.8-27B-DFlash2` (bf16) checkpoint via chad's own `chad.mlx_dflash`
  conversion tool (`--bits 4 --group-size 64`), so the draft head is reproducible without
  access to any private repo.
- Added `chat_client.py`: the only place in this project that knows chad's `/completion`
  SSE wire protocol (llama.cpp-style). Provides `complete()` (streaming) and
  `complete_sync()` (collects full text + timings).
- Documented the chat backend in `README.md`, including the corrected benchmark figures.
- Locally, symlinked the existing on-disk draft artifact at
  `~/dflash2-mlx/models/chad-dflash-sidecar-w4gs64` into `models/dflash2-w4gs64` to avoid
  rebuilding it; gitignored and local-only, same as the target model symlink.

## Notes, assumptions, limitations

- The 7-token smoke-test response is a correctness check only, not a throughput
  measurement — no tok/s figure should be read from it. The benchmark figures cited in
  the README (~65 tok/s baseline, ~66 tok/s with LibraSpec) come from
  `dflash2-mlx/README.md`'s own "Cross-runtime comparison" table, not from this session's
  own timing run (per this machine's GPU-timing discipline: comparable numbers require a
  thermally-gated, dedicated timing run, which wasn't performed here).
- LibraSpec requires the user's private `git@github.com:kaarelkaarelson/chad.git`
  (branch `libraspec-algo1`) checked out locally; teammates without access to it will
  transparently fall back to the public package (same target/draft pair, no LibraSpec,
  ~65 tok/s instead of ~66).
- `scripts/build_dflash_draft.sh` was not exercised in this session (the existing local
  artifact was symlinked instead) — worth a teammate running it once from a clean
  checkout to confirm it reproduces the draft correctly.
