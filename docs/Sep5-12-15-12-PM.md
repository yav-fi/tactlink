# Autonomous behaviour + motion/mission planning engine

**Completed:** 2026-09-05 12:15:12 EDT (America/New_York)

## Prompt

Build the missing autonomy layer for the decentralized drone command monorepo: a
local, deterministic package that converts structured mission tasks plus a
drone's local world knowledge into safe paths and actions. Must not rebuild the
simulation, environment, interface, llms, or mobile packages, must not use any
network/model/cloud service, and must keep tests small and targeted.

## What changed

New package `planning/` (12 modules + README), one test module, one pyproject line.

- `planning/models.py` — typed contracts: `Vector3`, `TaskSpec`, `PlanningContext`
  (dataclass, holds the environment port), `PlannerResult`, `PlanningConfig`
  (every threshold in one place), obstacle/region models, and the `PlanMode`,
  `BehaviorPhase`, `PlanWarning`, `CompletionKind` enums.
- `planning/environment.py` — `EnvironmentQuery` protocol plus `SimpleEnvironment`
  (axis-aligned boxes, circles, polygons, 2.5D height handling) and
  `environment_from_dict` for simulator world dumps.
- `planning/geometry.py` — pure helpers (segment/AABB, polygon clipping, centroids).
- `planning/pathfinding.py` — deterministic 8-connected grid A* over inflated
  obstacles with corner-cut guarding, line-of-sight string pulling, a clearance
  ladder, and a full-world retry when the padded search window is boxed in.
- `planning/coordination.py` — active-team roster derived from local peer belief,
  contiguous work splitting, ring slots, altitude layering.
- `planning/deconfliction.py` — structural altitude stratification plus reactive
  yielding (priority, then lexicographic id) with a lateral detour and route rejoin.
- `planning/energy.py` — reserve-aware feasibility that keeps the longest
  affordable route prefix.
- `planning/behaviors/` — GOTO/HOLD/RETURN, SEARCH (boustrophedon lanes divided
  across the team), WATCH (standoff ring, never the centre), TRACE (route
  validation + stagger), FOLLOW (standoff tracking, observation only), REGROUP
  (formation slots).
- `planning/planner.py` — `MissionPlanner.plan()` running
  behaviour → routing → energy → deconfliction → motion output, plus
  `should_replan()` and per-(drone, task) behaviour state.
- `planning/adapters.py` — structural bridges so `planning` never imports
  `simulation`: `context_from_node`, `task_spec_from_mission_task`,
  `environment_from_world_definition`, `motion_intent_from_result`.
- `planning/demo.py` — `python -m planning.demo`, eight scenarios, no UI.
- `tests/test_planning.py` — 8 targeted tests.
- `pyproject.toml` — added `planning*` to `tool.setuptools.packages.find`.

No teammate-owned files were modified.

## Notes, assumptions, limitations

- Planning is 2.5D: A* searches x/y at one assigned altitude; vertical movement
  is used only for deconfliction layering.
- Deconfliction is reactive and pairwise, not time-parameterised.
- Energy is distance-only (no wind, hover, climb, or payload cost).
- Region geometry, altitude, standoff, and lane spacing ride in
  `MissionTask.metadata`, so the simulator's canonical contract is unchanged.
- SEARCH lane retirement is proximity-based unless the simulator calls
  `planner.mark_lane_complete`.
