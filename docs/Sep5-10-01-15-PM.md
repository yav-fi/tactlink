# iPhone position/heading ingest into the gesture-quad sim

Completed: 2026-09-05 10:01:15 PM EDT (America/New_York)

## Prompt

Combine the merged SignalMap iPhone app (`alvan-ios`) with the webcam
gesture-quad simulator: the phones stream camera-mount position + heading, the
sim builds one operator per phone at its real spot and facing. Do both the iOS
and Python sides; double-check nothing in the push breaks.

Scope chosen this round (see follow-ups): **telemetry only** — phones send
position + heading, gestures still come from the laptop webcam.

## What changed

### Python — the ingest layer

- **`src/phone_feed.py`** (new). `PhoneFeed` runs a daemon UDP listener, keeps
  the newest datagram per phone id, and prunes any phone that goes quiet
  (`stale_sec`, default 2 s). `parse_datagram` validates the JSON and rejects
  anything malformed. `PhoneReport` is the parsed record.
- **`src/operators.py`**. New `OperatorPool.sync_from_reports(reports, rot,
  recenter)` rebuilds the operator list from live reports: matches existing
  `Operator` objects by phone id (updates pos/heading in place), adds new phones,
  drops missing ones. `rot` rotates the phones' arbitrary UWB frame into the sim
  frame; `recenter` subtracts the group centroid, **locked on the first non-empty
  sync** (`_sync_origin`) so drone↔operator geometry stays stable as people walk.
  `set_active_by_proximity` and `resolve_forward_bearing` now no-op safely with
  zero operators. `Operator` gained an `op_id` field.
- **`src/main.py`**. New `--phone-feed [HOST:]PORT` and `--phone-frame-rot DEG`.
  When `--phone-feed` is set the operators come from the feed each frame instead
  of the simulated ring/wander; the proximity-control block is guarded for the
  no-phones-yet case; the feed is stopped in the `finally`. Everything else
  (webcam gestures, proximity authority, dash/leash, demo, runtime, check modes)
  is unchanged.
- **`scripts/mock_phone_feed.py`** (new). Fakes N phones walking a circle so
  `--phone-feed` can be exercised with no iPhone/UWB/Wi-Fi.
- **`tests/test_phone_feed.py`** (new, 10 tests, standalone + pytest): datagram
  parse/reject, UDP receive over loopback, stale pruning, `from_arg`, and the
  pool sync (add/update/drop, rotation, fixed origin, heading follow).

### iOS — the visualizer bridge

- **`ios/SignalMap/RoomBridge.swift`** (new). One-way UDP sender. Each phone
  streams its own group-frame position + `RelativeMotionHeading` (~10 Hz, capped
  ~15 Hz) as small JSON to a configured `host:port`. Never receives. Carries no
  room code, NI tokens, or other phones' data. A reserved `gesture` field is
  always `"None"` (the app still does not use the camera).
- **`ios/SignalMap/RoomSession.swift`**. Owns a `RoomBridge`; new persisted
  `@Published var simBridge` ("host:port", empty = off); reads a `--sim-bridge`
  launch argument in `init`; `configure` on join, `stop` on leave; sends this
  phone's `geometry.positions[localID]` from `tick()` once a cycle has resolved.
- **`ios/SignalMap/RoomView.swift`**. "Visualizer host (optional)" field in the
  lobby, bound to `simBridge`.
- **`ios/SignalMap.xcodeproj/project.pbxproj`**. `RoomBridge.swift` added to the
  file refs, the `SignalMap` group, and the Sources build phase.
- **`ios/scripts/test-protocol.sh`**. `RoomBridge.swift` added to the `swiftc`
  file list (the protocol test compiles `RoomSession.swift`, which now
  references it).
- **`ios/README.md`** / **`README.md`**. New "Visualizer bridge" / `--phone-feed`
  sections; layout table rows; the "no camera/GPS/internet" line now notes the
  optional local-network stream.

## Notes / limitations

- **iOS is not compiled here** (Windows machine — no Xcode). The Swift is
  review-only; `sh scripts/test-protocol.sh` and a device build must be run on
  the Mac before shipping to phones. The change is one new file plus a ~20-line
  wiring diff to keep that review small.
- Work was done in a separate git worktree off `origin/main` because a
  concurrent workstream has uncommitted changes in the shared tree that block a
  pull; that tree was left untouched.
- **Frame alignment is manual** (`--phone-frame-rot`). UWB gives no north; a
  proper fix is a compass heading from one phone. Recenter is a one-time origin
  lock, not continuous.
- **Gestures are still webcam-only.** The wire format already carries a
  `gesture` field so on-phone recognition can be added later without a protocol
  change.
- Handoff/anchor/leash behaviour is unchanged — the feed only supplies operator
  positions and facings; proximity still decides authority.
