# Remove the drone motion-trace particles

Completed: 2026-09-06 02:52:13 AM EDT (-0400)

## Prompt

Remove the tracing dots that follow the drone while it moves, which should also
remove rendering effort.

## What changed

- Deleted the 72 red particle entities each `DroneController` created in its
  constructor, along with `recordMotionTrace`, `sprayParticle`, `tracePoint`,
  and `traceAlpha`, the `traceSamples`/`traceSequence` state, and their cleanup
  in `destroy` and `reset`.
- Deleted `3d-mapping/src/motion-trace.ts`.
- Dropped the particle-fade unit test and replaced the deploy test's particle
  assertions with a check that a deployed drone adds no trace entities at all.
- Updated the README line that described the particle spray.

`TRAIL_COLOR` and the hidden route polyline stay: route history is still
recorded internally for replay, and start/release markers are unchanged.

## Rendering effort removed

Each drone ran 72 point entities whose position, show, pixelSize, color, and
outlineColor were all non-constant `CallbackProperty` instances. Cesium
re-evaluated every one of them on every frame, so each drone cost 360 property
evaluations plus 72 point-primitive writes per frame, whether or not it was
moving. A nine-drone fleet was spending 3,240 property evaluations and 648
primitive updates per frame on the trail alone. That is now zero.
