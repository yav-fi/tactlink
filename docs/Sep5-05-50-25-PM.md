# Thumbs-up steps altitude; target-altitude hold

Completed: 2026-09-05 05:50:25 PM EDT (America/New_York)

## Prompt

Once the drone is airborne, every thumbs-up should raise its height. Plus a
question: is MediaPipe local, and does it only use finger vectors? (answered in
chat - yes, fully on-device TFLite; it runs CNNs on the camera image to get the
21 landmarks, then a small head classifies the gesture from those landmarks.)

## What changed - `src/controls.py`

- Single source of truth for height: `self._alt_target`. `_alt_throttle(state)`
  is a damped P controller (position error 1.3, velocity term 0.45) that every
  idle/hover frame and every maneuver now uses to hold altitude.
- `takeoff` event: if not armed -> arm + `_alt_target = _TAKEOFF_ALT` (1.3 m);
  if already airborne -> `_alt_target += _CLIMB_STEP` (1.5 m), capped at
  `_MAX_ALT` (9 m). Runs a `climb` maneuver (was `takeoff`) for HUD feedback,
  clears within 0.25 m of target.
- `land` / `estop` set `_alt_target = 0`.
- Removed the per-maneuver altitude snapshots (`_dash_alt`, `_orbit_alt`);
  `return_home` now holds altitude too.
- `src/visualizer.py` - hint reads `thumb up=takeoff/rise`.
- `src/main.py` - demo fires a second `Thumb_Up` at t=4 s to show the step.
- `tests/test_fly_maneuver.py` - `_armed_at()` helper sets `_alt_target` like a
  real takeoff would; new `test_takeoff_then_thumbs_up_steps_altitude` and
  `test_takeoff_holds_base_altitude`.
- README - Thumb-up row.

## Notes

- `_CLIMB_STEP` (1.5), `_MAX_ALT` (9), and the `_alt_throttle` gains are
  constants in `controls.py`.
- There is no "step down" gesture; thumb-down lands. A descend-by-step could map
  to a spare gesture later.
