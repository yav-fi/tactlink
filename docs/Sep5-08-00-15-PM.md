# Dashes leave the drone in place; operators face north

Completed: 2026-09-05 08:00:15 PM EDT (America/New_York)

## Prompt

1. The drone shouldn't return home every time it dashes east/west - it was
   springing back to the operator after each dash.
2. Rotate the operators to face north.

## Cause of #1

After a dash maneuver cleared, the idle behaviour (`_follow_point`) trailed the
operator - so a 5 m dash then drifted 5 m back.

## What changed

- `src/controls.py` - `GestureController._leashed` flag gates idle-follow:
  - set **True** on `takeoff` and on `return_home` (drone sits with the operator)
  - set **False** on any dash (`fly_*` / `fly_bearing`) and when `orbit` stops
  - idle-follow branch now requires `self._leashed`
  So after a dash the drone holds position; `return_home` brings it back and
  re-leashes.
  (Also folded the `_COMPASS` and `fly_bearing:` branches together.)
- `src/operators.py` - operators initialise facing **north** (`heading = pi/2`,
  world +y) instead of facing inward.
- `src/main.py` - demo operators face north too.
- Tests: `test_fly_maneuver` `_armed_at` now sets `_leashed`; +2
  (`test_drone_holds_position_after_a_dash...`, `test_return_home_re_leashes...`).

## Verification

- `python -m py_compile src/*.py tests/*.py` clean; all suites green
  (operators 6, finger_swing 9, fly_maneuver 14, swarm 5, sequences 10).
- `--demo` at t=15 s (after the east dash): `MODE HOLD`, `spd 0.7 m/s` - the
  swarm holds its dashed position, not drifting back to the operator.
- `--demo --check-gestures`: three-finger now logs `fly_bearing:1.5708` (north,
  because operators face north).

## Notes

- `orbit` stopping (repeat gesture) also unleashes - drone hovers at the ring.
- The operator heading arrow in the 3D view now points +y (into the scene from
  the default camera); purely cosmetic.
