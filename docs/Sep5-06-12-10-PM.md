# Drone swarm - squad formation flight

Completed: 2026-09-05 06:12:10 PM EDT (America/New_York)

## Prompt

Command a drone swarm (and later be able to single one out). For now: squad
formation - one gesture drives the whole group.

## What changed

- `src/swarm.py` (new) - `Swarm(n)`: drone 0 is the leader and runs the full
  `GestureController` (identical to the single-drone path), drones 1..n-1 hold a
  ring formation around it via a per-drone position/altitude/yaw follower
  (`_follow`). `formation_slots(n)` = leader at centre + the rest evenly on a
  2.8 m ring, so the formation centroid stays on the leader and return-home
  recentres the squad on the origin. `n = 1` is exactly the old behaviour.
  `Swarm.selected` is the hook for per-drone commanding later.
- `src/visualizer.py` - `render()` now takes a list of states + trails, draws
  every drone (far-to-near), rings the `selected` one in cyan, frames the
  centroid, and the HUD shows `ARMED xN` / `sel #k` and centroid altitude.
- `src/main.py` - `--drones N` (default 5); the run loop uses `Swarm`; `1`-`9`
  keys set `swarm.selected`; `space` / `r` updated. Dropped the now-unused
  `GestureController` / `QuadSimulator` imports.
- `tests/test_swarm.py` (new, 5) - slot shape/balance, n=1 == single flight,
  whole squad takes off together, formation held through a dash, return-home
  recentres the squad.
- README - Run list, new "Swarm" section, layout row.

## Notes / limitations

- Followers lag the leader by up to ~1 m during hard maneuvers (P-only follower,
  gain 0.9) - fine visually, tighten in `swarm.py` if needed.
- During `orbit` the whole ring revolves rigidly around the origin (outer drones
  cover more ground) - reads as a formation orbit.
- No per-drone commanding yet: `1`-`9` only highlight. Single-out would route the
  gesture stream to `drones[selected]` with its own controller.
- `land` / `estop` drop followers straight down (sim ignores roll/pitch when
  disarmed); they land roughly in formation.
