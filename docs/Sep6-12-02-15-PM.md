## The Victory bug

`Sim.advance` suppressed the Victory gate whenever `FingerSwingDetector.active`
was true. But a Victory sign *is* an index+middle two-finger pose, so holding it
put one "V" entry in the swing detector's history -> `.active` went true ->
Victory suppressed itself and the hand-off timer never ran. Removed the
suppression entirely: the dash gesture now points *sideways* and Victory points
*up*, so MediaPipe's own classification keeps them apart and no cross-suppression
is needed.

## What changed

- **`gestures.py`**
  - Removed `FingerSwingDetector` / `orientation` / `dash_from_point` (the
    vertical<->horizontal swing - hard to perform reliably on a webcam).
  - New `SidePointDash`: hold the index finger pointing clearly left/right for
    ~0.45 s -> `dash_east` / `dash_west`. A held pose, not a motion.
  - `Victory` hold 2.0 s -> 1.5 s. `hand_from_landmarks` finger-extended test
    loosened (`* 1.02`), and `point_dir` folds in the middle finger only when
    it's actually extended.
- **`gesture_demo.py`**
  - `Sim.advance` drops the Victory suppression, runs `SidePointDash`.
  - The webcam panel now **always** shows the raw model output and finger states
    (`model: Victory 71%   fingers -IM--`). New `--diag` prints the same each
    frame to the console.
  - `--threshold` default 0.5 -> 0.45.
- **`scene.py`** - dash hold-progress bar; updated hint line.
- **`test_gesture_demo.py`** - `WiperTests` -> `SidePointDashTests`; 13 tests.
- README updated.
