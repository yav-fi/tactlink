Completed: 2026-09-06 04:35:29 EDT (-0400), America/New_York.

## Prompt

Add a two-phone mode with an explicitly assumed alignment so camera gestures and the single simulated drone can be tested without a third phone, accepting that the map direction may be wrong.

## Changes

- Added a mutually exclusive **2-phone gesture test** toggle alongside the existing three-phone test. New room codes beginning with 2 select it automatically. Mode control and profiles carry an optional two-phone flag; switching modes clears existing geometry and waits for the new participant count.
- Two real UWB peers auto-start the existing ranging protocol. One valid measured distance d places the sorted phone IDs at (0, -d/2, 0) and (0, +d/2, 0). This is a vertical line on the map, not physical height. Missing/invalid ranges never produce positions. Snapshot validation requires the explicit assumption flag.
- Phone UDP telemetry and the browser propagate and display the two-phone mode. The same compass-facing, gesture hold, controller selection, and single-drone flight path apply. Rooms and modes are not mixed.
- Preserved three-phone flat and five-phone XYZ behavior. Updated launcher text, setup documentation, and synthetic feed (two-phone mode uses a fixed line).
- Built and signed native app build 1788683637 and published it to the existing automatic installer. The live local frontend was rebuilt; the backend reloads the telemetry field change.
