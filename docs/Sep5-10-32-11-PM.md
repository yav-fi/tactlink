# Per-operator gesture interpreters (phone-gesture routing, piece 1)

Completed: 2026-09-05 10:32:11 PM EDT (America/New_York)

## Prompt

Toward on-phone gesture recognition. Piece 1 of 3: route each phone's own
gesture label through its own interpreter so the drone responds to the
controlling operator, before any Swift camera code exists. (Piece 2 = compass
heading; piece 3 = the iOS MediaPipe recognizer.)

## What changed

- **`src/operator_gestures.py`** (new). `OperatorGestures` keeps one
  `GestureInterpreter` per operator (keyed by phone id, or name for the
  simulated pool), steps them all each frame, and returns the `GestureState` of
  whichever operator currently holds control. Everyone else's events are
  computed and dropped — that is what enforces "only the nearest operator flies
  the drone". The webcam gesture fills in for the active operator only when that
  operator's own gesture is `"None"` (bring-up aid; a real phone gesture wins).
  Interpreters for departed operators are pruned.
- **`src/operators.py`**. `Operator` gained `gesture` / `gesture_source`;
  `OperatorPool.sync_from_reports` copies them from each `PhoneReport`.
- **`src/phone_feed.py`**. `PhoneReport.gesture_source`; `parse_datagram` reads
  an optional `gestureSource` wire field.
- **`src/main.py`**. Replaced the single module-level `GestureInterpreter` with
  `OperatorGestures`. The per-frame order is now sync operators → step → pick
  the controller → run every operator's interpreter → the controller's state
  drives the drone. New `--no-camera` flag: skip the webcam entirely so the
  laptop is a pure ground station (gestures only from the phone feed).
- **`scripts/mock_phone_feed.py`**. `--script` makes phone 1 run a looping
  gesture timeline (take off, take off, orbit, halt, land) so the whole path can
  be exercised with no hardware and no webcam.
- **`tests/test_operator_gestures.py`** (new, 7 tests): active fires / non-active
  ignored / webcam fill-in / phone beats webcam / pruning / fresh interpreter on
  handoff / simulated pool unchanged.
- README: Operators section + layout table.

## Notes

- Behaviour change for the simulated multi-operator pool: on a control handoff
  the new operator's interpreter starts fresh (its own hold timing), where the
  old single interpreter carried state across. This is more correct — each
  person's gesture timing is their own — and does not affect `--operators 1`
  (the default) or the `--demo`.
- Phones still send `gesture: "None"`; nothing recognises hand poses on-device
  yet. The wire path and the sim side are now proven, so piece 3 only has to
  fill in the label.
- Done in a throwaway git worktree off `origin/main`; the shared working tree
  (teammate's uncommitted work) was not touched.
