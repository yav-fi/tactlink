# Distributed mission simulation runtime

Completed: 2026-09-05 12:06:34 PM EDT (America/New_York)

## Prompt

Build the core simulation and distributed mission runtime for a defense-oriented autonomous-systems hackathon monorepo. The requested vertical slice needed simulator-owned ground truth, autonomous nodes limited to local knowledge, typed mission commands, deterministic allocation and failure reassignment, degraded GPS and peer networking, seeded scenarios, structured events, FastAPI REST/WebSocket access, a minimal localhost console, an end-to-end demo, and meaningful tests.

## What changed

- Added the typed `simulation/` package with separate configuration, contracts, event bus, world truth, portable node autonomy, network delivery, interference, task allocation, mission management, scenario generation, central clock, and demo modules.
- Enforced the truth boundary structurally: only `World` stores actual positions, velocities, health, and battery; `DroneNode` accepts local measurements, delivered messages, and assignments and produces message/motion intents.
- Implemented all requested mission primitive schemas, including waypoint execution for TRACE, generated region coverage for SEARCH, local moving-entity measurements for FOLLOW, node-local home behavior for RETURN, and point behaviors for GOTO/WATCH/HOLD/REGROUP.
- Added deterministic scoring, delayed heartbeat failure detection, orphaned-task reassignment, per-task capability, and weighted overall mission capability.
- Added seeded latency, jitter, packet loss, bandwidth limits, optional duplication, partitions, reconnection, GPS outage/noise/dead reckoning, sensor-confidence degradation, and per-second node failure probability.
- Added structured bounded events for simulation, network, localization, failure, allocation, autonomy, and mission transitions.
- Added a FastAPI server with typed REST endpoints and `/ws` state snapshots, plus a compact browser console with drone truth/estimate comparison, peer ages, links, missions, capability, events, presets, sliders, and controls.
- Added an accelerated four-drone demo and integration tests covering motion, localization truth separation, seeded packet loss, delayed peer loss, failure reallocation, capability recovery, partitions/reconnection, scenario determinism, REST, WebSocket serialization, and controls.
- Added Python packaging/dependencies, ignore rules, and setup/integration documentation.

## Notes and limitations

- This is a mission/network software simulator, not a flight dynamics model, RF propagation solver, GPS-denied navigation solution, security implementation, or deployment-ready safety system.
- Motion is bounded point-mass movement. Obstacles and regions have adapter-ready schemas, but obstacle avoidance and terrain-aware planning remain future work.
- Nodes run in one process today. Protocol seams isolate transport, sensing, motion control, and status publication so separate-process or separate-laptop adapters can follow.
- Trust, authorization, public-key, and message-signature fields are placeholders only; no security claims are made.
- The test run reports two deprecation warnings inside the current Starlette test-client dependency path; no project test failed.
- An unrelated untracked `planning/` directory appeared in the worktree and was intentionally not changed or included with this prompt.
