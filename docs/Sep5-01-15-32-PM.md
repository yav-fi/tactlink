# Connect operator inputs to canonical missions

Completed: 2026-09-05 01:15:32 PM EDT (America/New_York)

## Prompt

Connect the existing local LLM and discrete gesture systems to the existing canonical `simulation.models.MissionCommand` pipeline and `POST /api/missions`, using one shared HTTP client without changing planner/runtime internals.

## What changed

- Added `integrations.llm_mission`, which calls the existing `chat_client.chat_sync` boundary with a JSON-only prompt, strips common Markdown fences, parses exactly one JSON object, validates the canonical Pydantic model, applies mission-target safety checks, and rejects malformed or unexpected fields without submission.
- Added the executable `python -m integrations.llm_mission` CLI with optional `--submit`, `--mission-url`, and `--chat-url` flags.
- Added `integrations.mission_client.MissionClient`, a small standard-library client shared by input adapters for mission submission and state retrieval.
- Added `GestureMissionAdapter.event_to_command`, mapping `Closed_Fist`/`land` to HOLD and `ILoveYou`/`return_home` to RETURN while allowing custom `mission:*` mappings and target-bearing context for other mission types.
- Added an opt-in `--mission-url` flag to the existing gesture application. Discrete supported events submit missions while continuous hand-axis piloting remains local and unchanged.
- Documented exact commands and custom gesture mappings.
- Added focused tests for valid/fenced LLM JSON, malformed JSON and schemas, semantic and unexpected-field rejection, gesture mappings, and canonical HTTP serialization.

## Verification

- All 30 combined repository tests passed.
- `python -m integrations.llm_mission --help` ran without loading the real model or emitting module warnings.
- Started the real FastAPI/Uvicorn runtime and submitted a canonical two-drone SEARCH through `MissionClient`; the endpoint returned HTTP 201 and a created runtime task.
- Python byte-compilation and `git diff --check` passed.

## Notes

- Unit tests stub the local LLM response boundary and do not require the model server.
- The natural-language CLI requires the existing local chat server/model when performing a real translation.
- Concurrent planner/runtime integration changes in `simulation/drone.py`, `simulation/simulation.py`, `simulation/autonomy.py`, and `tests/test_simulation.py` were neither edited nor staged by this work.
- Target-requiring custom gesture missions need a caller-provided `GestureMissionContext`; the current webcam event stream submits HOLD and RETURN directly.
