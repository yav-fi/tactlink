# Three-gesture on-device approach

Completed: 2026-09-06T05:36:12.610044-04:00 (EDT), America/New_York.

Prompt: Recommend a better on-device detector for only fist-to-call, index-point-up to ascend, and index-point-down to descend.

Recommendation: For the current demo, retain the already integrated Apple Vision hand landmarks and replace the broad heuristic classifier with two hand-shape decisions (fist and index-only pointing), a signed pointing-direction check, and a temporal state machine. Use hand-relative finger bend/curl features, confidence only for necessary evidence, neutral output for ambiguous/horizontal hands, smoothing, separate acceptance/release criteria, and a brief missing-observation grace period. Initial proposed confirmation windows are roughly 200–300 ms and must be tuned from physical samples. Fist selects/latches the caller, pointing changes vertical movement while held, and release returns to hover. Existing follow behavior should survive ambiguous frames; other old gestures would be removed when implemented. This is a proposed design, not a measured accuracy improvement or implementation.

Researched official alternatives: MediaPipe Gesture Recognizer supports native iOS live-stream operation and a bundled model, but its documented canned classes include Closed_Fist and Pointing_Up and no Pointing_Down. It would still need direction logic or a custom classifier for this exact gesture set and introduces CocoaPods integration. Apple's Create ML supports learned hand-pose classifiers if physical-data evaluation later justifies training. No claim that Vision or MediaPipe is empirically more accurate on these phones was made.
