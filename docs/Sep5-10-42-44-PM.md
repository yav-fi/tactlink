# Absolute compass heading for phone operators (piece 2)

Completed: 2026-09-05 10:42:44 PM EDT (America/New_York)

## Prompt

Piece 2 of the on-phone-gesture work: give each phone operator an absolute
facing so "forward" works while standing still, instead of only the
walking-derived `RelativeMotionHeading`.

## What changed

### iOS

- **`ios/SignalMap/HeadingSource.swift`** (new). Wraps `CMMotionManager`
  device-motion with the `.xMagneticNorthZVertical` reference frame - no
  location permission, no GPS, no internet. Exposes `compassDegrees` (degrees
  clockwise from **magnetic** north) computed from the screen-forward (device
  +Z) axis projected onto the horizontal plane; `nil` when the phone is near
  flat. The projection math is a pure static func (`bearing(north:west:)`),
  compiled and testable even under `-D ROOM_PROTOCOL_TEST` where CoreMotion is
  `#if`'d out to stubs.
- **`RoomBridge.swift`**. `send(...)` takes `compassDegrees: Double?`; the
  datagram gains `compass` (degrees) and `compassValid` (bool).
- **`RoomSession.swift`**. Owns a `HeadingSource`; starts it on join/foreground
  when a visualizer host is set, stops it on leave/background; passes
  `compass.compassDegrees` into `bridge.send` from `tick()`.
- **`project.pbxproj`**, **`scripts/test-protocol.sh`** - `HeadingSource.swift`
  registered in the build and the protocol-test file list.
- No Info.plist change: raw `CMMotionManager` device motion needs no usage
  string (only `CMMotionActivityManager` / pedometer do).

### Python

- **`src/phone_feed.py`**. `PhoneReport` gains `compass` / `compass_valid` and a
  `sim_heading(rot)` method: uses `radians(90 - compass)` when the compass is
  valid (absolute, `rot` ignored), else `heading + rot` (the UWB-frame motion
  heading). `parse_datagram` reads `compass` / `compassValid`.
- **`src/operators.py`**. `sync_from_reports` calls `r.sim_heading(rot)` when
  available (falls back to `heading + rot` for duck-typed reports). `rot` still
  always rotates *positions*.
- **`scripts/mock_phone_feed.py`**. Sends `compass` derived from each fake
  phone's facing; `--no-compass` omits it to exercise the fallback.
- **`tests/test_phone_feed.py`** +3: parse compass, `sim_heading` preference and
  fallback, pool uses compass for facing.

## Notes / limitations

- **Magnetic**, not true, north. All phones in one location share the reference,
  so they agree with each other; declination + any mount-angle offset is a
  single constant applied on the sim with `--phone-frame-rot`.
- Two on-device unknowns to confirm on the Mac/phone: (1) `CMAttitude.rotation
  Matrix` column 3 is the device +Z axis in the reference frame, (2) the wearer
  faces along device +Z (screen-out, upright mount). If either is off it is a
  sign flip or a 180 in `HeadingSource.bearing` plus the test.
- Positions are still UWB-frame-arbitrary; compass only fixes *facing*. Aligning
  the position frame to north (from multi-phone compass + geometry) is a later
  step.
- Worktree off `origin/main`; shared tree untouched.
