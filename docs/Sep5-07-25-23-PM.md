# Three-finger gesture: drop the orientation requirement

Completed: 2026-09-05 07:25:23 PM EDT (America/New_York)

## Prompt

User was confused that a "bearing" seemed to come from the fingers, and found the
sideways hold hard - especially pointing the fingers toward the camera.

## Clarification

The three-finger sign is only a **trigger** ("go forward"); it carries no
direction. The bearing comes from the **operator's facing** (chest phone compass
/ operator-agent heading). `fly_forward` -> `main.py` rewrites to
`fly_bearing:<active operator heading>`. You aim by turning your body.

## What changed - `src/finger_swing.py`

- Dropped `_is_sideways` / the horizontal-orientation gate from
  `ThreeFingerForward`. It added nothing (direction was never from the fingers)
  and was awkward + unreliable (fingers toward the lens foreshorten and stop
  registering as extended). Now: **index+middle+ring extended, pinky down, held
  ~0.45 s**, any orientation.
- `_THREE_HOLD_SEC` 0.35 -> 0.45, release 0.35 -> 0.4 (a touch more deliberate
  now that orientation isn't a filter).
- `src/main.py` check-gestures debug line drops the `sideways=` field.
- Tests: `test_three_fingers_orientation_does_not_matter` (fingers up still
  fires), `test_three_fingers_brief_flash_does_not_fire`.

## Verification

- `python -m py_compile src/*.py tests/*.py` clean; all suites green
  (finger_swing 9, fly_maneuver 10, swarm 5, sequences 10, operators 5).
- `--demo --check-gestures` still logs `fly_bearing:0.0000` from the three-finger
  window.

## For the user

Hold three fingers (pinky curled) anywhere the camera sees them - up is fine -
for ~half a second. `3finger=True` in the console, then `fly_bearing:...`. The
drone flies whichever way you (the controlling operator) face.
