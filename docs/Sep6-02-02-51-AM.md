# MediaPipe on iOS feasibility review

- Completed: 2026-09-06 02:02:51 AM EDT (-0400)
- Prompt: Determine whether the repository's native iOS app can use its iPhone camera to run MediaPipe pose, hand-landmark, and gesture detection.

## Summary

MediaPipe Tasks supports native iOS camera input and live-stream inference, so the feature is feasible in the existing SwiftUI app on a physical iPhone. The current iOS target does not yet have a camera capture pipeline, camera usage description, MediaPipe dependency, or bundled task model. Its UWB/Nearby Interaction implementation deliberately runs without camera assistance, but that does not inherently prevent adding a separate AVCaptureSession for MediaPipe.

## What changed

No application code was changed. This file records the repository-specific feasibility review.

## Verification

- Inspected the iOS target, Info.plist, project build settings, RoomView, RoomSession, RoomRanging, and RoomBridge.
- Inspected the existing Python MediaPipe GestureRecognizer and custom landmark-classifier pipeline.
- Checked Google's current MediaPipe Tasks iOS setup and Swift live-stream API documentation.

## Notes and limitations

- Google's documented MediaPipe Tasks iOS distribution currently uses CocoaPods (`MediaPipeTasksVision`) and a model file bundled with the app.
- The existing Python code cannot execute unchanged inside the native Swift app. The built-in GestureRecognizer can be mirrored with the iOS Tasks API; custom feature extraction/classification would need a small Swift port or another exported model format.
- A physical device is needed to validate camera behavior, frame rate, heat, and coexistence with sustained Nearby Interaction/network activity.
- Adding camera capture requires `NSCameraUsageDescription`, permission handling, lifecycle cleanup, and UI wording updates because the app currently explicitly advertises that it uses no camera.
