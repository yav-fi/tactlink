# Gesture startup repair

Completed: September 5, 2026 at 11:25:15 PM EDT (UTC-04:00)

## Prompt

Repair `./start` after the native MediaPipe gesture worker aborted on macOS with
a Metal graph-service failure, the gesture connection never became active, and
npm warned that the resolved Cesium and Vite releases did not support Node
20.13.0.

## What changed

- Replaced the native Python/OpenCV gesture bridge with MediaPipe Tasks Vision
  running locally in the main browser page through WASM.
- The browser requests the camera when the local flight sandbox opens, keeps the
  video element detached from the DOM, and only exposes gesture name,
  confidence, and hold progress to the mission HUD.
- Added deliberate 400 ms gesture holds and a 150 ms neutral release before the
  same command can fire again.
- Bundled the gesture recognizer model and WASM assets with the production app,
  so gesture startup does not require a runtime model download.
- Removed the temporary Python gesture API, worker, dependencies, and tests that
  are no longer part of the startup path.
- Pinned Cesium 1.129.0 and Vite 6.4.3. Their declared engine ranges support the
  project's Node 20.13.0 environment, and npm installation no longer emits the
  reported engine warnings.
- Made `./start` validate installed frontend dependencies and rebuild the
  production frontend even if a server is already listening on port 5173.
- Updated the one-command-demo documentation and startup output with the browser
  camera permission behavior.

## Notes

Camera frames stay in the browser and are not rendered, recorded, uploaded, or
sent to the Python runtime. The real camera-permission prompt and live gesture
recognition require an interactive browser and camera, so those cannot be
exercised by the headless test environment. If camera access was previously
denied for `127.0.0.1`, allow it in the browser's site settings and reload.
