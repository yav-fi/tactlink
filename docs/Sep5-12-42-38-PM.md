# Gesture recognition: modes + discrete commands

Completed: 2026-09-05 12:42:38 PM EDT (America/New_York)

## Prompt

"I want to make more specific hand signs. Additionally, who made the model that
is reading the hand gestures." User chose the **MediaPipe GestureRecognizer**
approach and a combination of **mode switching** and **discrete commands**.

Model provenance: the hand model is Google's (MediaPipe team). Landmarks come
from the MediaPipe Hands model (Zhang et al., Google Research, 2020) - a palm
detector plus a 21-keypoint regressor. `GestureRecognizer` adds a Google-trained
classification head over those keypoints for 7 canned gestures. The
gesture->drone-action mapping is all local code.

## What changed

- `src/hand_tracker.py` - switched from `HandLandmarker` to `GestureRecognizer`
  (also a Tasks API, VIDEO mode). Now downloads `gesture_recognizer.task` (~8 MB)
  and returns the gesture label + score alongside the landmark-derived fields.
- `src/control_types.py` - added `FlightMode` enum (HEADING / POSITION / HOVER),
  `GestureState` dataclass, and `gesture` / `gesture_score` on `HandState`.
- `src/gestures.py` (new) - `GestureInterpreter`: hold-to-fire debouncing
  (~0.4 s), one-shot-per-press with a release gap, mode cycling (Victory), speed
  profile slow/normal/sport (Thumb_Up / Thumb_Down), and discrete events
  (takeoff, land, spin360, return_home).
- `src/controls.py` - `GestureController.update(hand, gstate, state)`. Mapping
  now depends on `FlightMode`; outputs scale with the speed profile. Discrete
  events run as short autopilot routines (`takeoff`, `land`, `spin360`,
  `return_home`) that override the hand until they complete.
- `src/simulator.py` - ground contact now also registers while armed if the
  drone is descending, so the landing routine can finish and disarm.
- `src/visualizer.py` - HUD shows `MODE` (red while an autopilot routine runs),
  `SPEED`, the active gesture, and a hold-progress bar.
- `src/main.py` - wires the interpreter in; scripted `--demo` now performs a
  full timeline (takeoff -> fly -> Victory -> Pointing_Up spin -> ILoveYou home
  -> Closed_Fist land); spacebar is a takeoff/land fallback.
- README - rewrote the flying + gestures sections and the layout table.

## Verification

- `python -m py_compile src/*.py` - clean.
- `GestureInterpreter` unit test: Open_Palm hold fires `takeoff` once; a repeated
  gesture with no release gap does not re-fire; after a gap it does; mode cycles
  heading->position->hover; speed caps at `sport`.
- `HandTracker` on real MediaPipe sample images: `fist`->Closed_Fist (0.91),
  `victory`->Victory (0.78), `thumb_up`->Thumb_Up (0.70), `pointing_up`->
  Pointing_Up (0.85); landmark fields still populated.
- `python src/main.py --demo --headless` rendered at t=8/14/20/27 s: confirmed
  mode change to POSITION, `SPIN360` autopilot (yaw bar pinned), `RETURN_HOME`
  autopilot (roll steering, trail curving to origin), and final `DISARMED` on the
  ground near the start point.

Live webcam not tested here (no camera); the recognizer was validated on stills.

## Notes / limitations

- The 7 gestures are fixed by Google's canned classifier. Custom signs would need
  `GestureRecognizer`'s custom-gesture training (out of scope here).
- `victory` reads as 3 fingers from the geometric counter; unused since arming is
  gesture-driven now.
- `models/hand_landmarker.task` from the previous version is now unused (still
  gitignored); safe to delete.
- Autopilot routines are open-loop-ish and tuned for the demo, not robust
  control.
