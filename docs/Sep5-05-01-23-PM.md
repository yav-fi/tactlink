# Passthrough class so custom gestures don't shadow built-ins

Completed: 2026-09-05 05:01:23 PM EDT (America/New_York)

## Prompt

After training `two_up` / `two_flat`, a one-finger point (canned `Pointing_Up` =
orbit) was being classified as `two_up` and overridden - the custom model has no
"one finger" reference so the point falls into its nearest cluster, and the
custom prediction always wins over the canned gesture.

## What changed

- `src/gesture_model.py` - `PASSTHROUGH_LABELS = {"other", "none", "neutral",
  "background", "ignore"}`. When `predict()` lands (confidently) on a class with
  one of those names it returns `(None, conf)`, so `hand_tracker` keeps the
  built-in MediaPipe gesture. Real gesture classes override as before.
- `scripts/train_gestures.py` - computes the reject radius over the *real*
  classes only (a broad passthrough class would inflate it); prints which
  passthrough classes are present.
- README - "if a custom label shadows a built-in" note.

## How to use it

Record a class named `other` holding everything that is NOT a wiper pose - thumbs
up/down, one-finger point, ILoveYou, fist, open/relaxed hand, transitions:

    python scripts/collect_gestures.py --label other      # cycle through those poses while recording
    python scripts/train_gestures.py                      # now 3 classes: two_up, two_flat, other

A one-finger point then classifies as `other` -> tracker keeps canned
`Pointing_Up` -> orbit fires. `two_up` / `two_flat` still override normally.

## Verification

- `python -m py_compile src/*.py scripts/*.py` clean; `tests/test_sequences.py`
  10/10, `tests/test_fly_maneuver.py` 6/6.
- Synthetic 3-class set (two_up, two_flat, other): 100 % 5-fold; a sample from
  the `other` cluster -> `predict` returns `(None, 1.0)` (passthrough); a
  `two_up` sample -> `('two_up', 1.0)`. Reject radius reported over the two real
  classes only.

## Notes

- Not tested on a real webcam here.
- `other` being broad is fine - it only ever means "use the canned result".
- If a genuine `two_up` still gets missed after adding `other`, lower the
  `train_gestures.py` reject-radius multiplier (currently 3.0) or record more
  `two_up` variety.
