# Add one-command demo and obstacle avoidance

**Completed:** September 5, 2026 at 7:45:38 PM EDT (UTC-04:00)

## Prompt

Reduce demo startup to one command and make drones attempt to fly around detected obstacles instead of immediately stopping.

## Summary

Added a root `./start` launcher that handles missing local dependencies, starts or reuses the Python runtime and Vite frontend, opens the local flight sandbox, and cleans up its child processes with one `Ctrl+C`. Replaced stop-first collision behavior with reactive local avoidance for manual flight, missions, destination commands, and playback.

## Changes

- Added the executable `start` launcher and documented it at the top of the root README.
- Added `avoidanceMove`, which checks the direct segment, progressively wider left/right candidates, and a climb candidate for non-descending flight.
- Integrated avoidance into manual movement, missions, and replay/destination movement.
- Changed the collision marker to `AUTO-AVOIDING`; `NO SAFE ROUTE` appears only after all candidates fail.
- Kept ground safety strict: a requested descent cannot silently turn into a climb.
- Updated fleet completion tracking so detouring destination flights are not marked arrived before reaching their actual endpoint.
- Updated the local-sandbox UI text and documentation.
- Added coverage for successful manual and mission detours while retaining no-safe-route tests.

## Notes

- Avoidance is reactive and uses geometry currently available to Cesium; it is not a global path planner and cannot see unloaded or offscreen tile geometry.
- If every lateral/climb candidate is blocked, the drone holds its last safe position and reports `NO SAFE ROUTE`.
